没错，2026 年的今天，我又来折腾博客方案了。这次和几年前不同——AI 的加持让一切变得不一样，再也不是前端无能的丈夫了（bushi）。

但 AI 解决的不应该只是帮助人类成为更好的全栈工程师。Agent 本身也应该成为读者。道理很简单：人类大脑带宽不足，新时代信息爆炸，读不完、看不完、学不完是常态。一小时的干货视频，消化它远远不止一小时；更别提在不熟悉的语言下，阅读速率就更低了。而 AI 以 token/s 的处理速度远超人类，更重要的是: 尽管人类可能像松鼠，收集了一季的橡果，入冬全忘；但 AI 可以快速"内化"到自己的知识库内, 无论何时, 快速找到这些橡果。

## 核心原则

在设计这个新框架之前，先定下几条基本原则：

- **AI 友好**：结构清晰、语义明确，让 Agent 能轻松解析和交互
- **轻量**：不依赖重型基础设施，个人就能部署和维护
- **极简**：日常只写 Markdown，和写笔记没有区别

## 什么是 Agent 友好的博客

传统博客的读者是人类。Agent 友好的博客则把 Agent 视为**一等公民**——它们不只是辅助作者写作的工具，更是独立的知识消费者。

这意味着博客需要为 Agent 提供：
- 结构化的内容访问（而非仅 HTML）
- 标准化的身份识别
- 可交互的接口: 操作博客网站内的资源

## 需求拆解

### Agent CLI 交互层

新框架对 Agent CLI 的交互友好，具体包括：

- **DID 身份系统**：Agent 在这个框架下有自己的去中心化身份
- **RSS 订阅**：Agent 可以作为订阅读者，自动抓取更新
- **跨站搜索**：支持 Agent 自己做搜索引擎，聚合多站内容
- **网站级 API**：允许 Agent 做 CRUD 交互
  - 读者 Agent：总结、收藏、翻译、提问某篇文章
  - 作者 Agent：在 CLI 发布、删除、更新文章
- **REPL 式交互**：提供注册手段，可以注册个人 Agent，通过网页下方的输入框类似 REPL 和网页交互
- **批注层**：Agent 可以看到讨论区，参与协作

### 传统兼容层

老框架的优良传统不能丢：

- **Markdown 优先**：日常只用编写 Markdown 文档
- **多平台同步**：支持一键更新到多个平台
- **发布者友好**：作者只需要编辑 Markdown，不用关心部署细节
