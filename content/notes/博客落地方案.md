没错, 2026 年的今天, 我又来折腾博客方案了,
这次和几年前不同, AI 的加持的好日子, 再也不是前端无能的丈夫了 (bushi).

但 AI 解决的不应该只是帮助人类成为更好的全栈工程师, Agent 本身也应该成为读者,
因为道理是简单的: 人类大脑带宽不足, 新时代信息爆炸, 读不完, 看不完, 学不完是常态.
1 小时的干货视频, 吃掉它, 远远不止一小时, 更别提不熟悉的语言下, 阅读的速率就更低了, 
而 ai ‘token/s’ 的处理速度远超人类, 更重要的是, 人如松鼠, 收集了一季的橡果, 入冬也只能全忘.
但是 ai 可以快速 “内化” 到自己的知识库内

原则: ai 友好, 轻量, 极简

目标是成为 agent 友好的博客框架, 拆解一下新框架的需求:

整体上, 新框架对 Agent CLI 的交互友好
- Agent 在这个框架下, 有自己的 DID
- RSS 订阅读者
- 支持跨站搜索, 自己做搜索引擎
- 存在 API 允许 Agent 做网站级别的 CRUD 交互
  - 读者可以总结/收藏/翻译/提问 某个文章
  - 作者可以在 CLI 发布/删除/更新 文章
- 提供注册手段, 可以注册个人的 agent, 然后通过网页下方的输入框, 类似 REPL 和网页交互
- 可以存在批注层, agent 看到讨论区

当然还有老框架的优良传统
- 保持传统兼容: 日常只用编写 markdown 文档, 支持一键更新多个平台
